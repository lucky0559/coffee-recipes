Rotation contract

Recipe identity continues to use daysSinceEpoch and queueIndexForDate. The featured panel and every recipe card use the rotation index and the position inside that rotation, so the phase is deterministic from the date and current recipe count.

rotationIndex = floor(elapsedDays / recipeCount)
positionInRotation = elapsedDays - rotationIndex * recipeCount
alternatingPosition = rotationIndex + positionInRotation
even → Hot · odd → Iced

13 recipes

First cycle: Hot, Iced, Hot … Hot. The next cycle begins Iced.

12 recipes

First cycle ends Iced. The requested reset begins Iced.

Empty or non-positive counts return Hot as a safe fallback. No API, persistence, transaction, locking, idempotency, or rollback behavior is involved.

User-facing behavior

  • The featured recipe and every list card start with their scheduled Hot/Iced build.
  • Manual Hot/Iced changes remain available and last for the current view.
  • At local midnight, recipe, queue, position, date label, and default build update together.
  • Upcoming queue previews and selections use the scheduled build for their future day.
  • Opening a recipe carries the active card or featured build into the modal.
